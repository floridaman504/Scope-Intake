# Scope API -- v1

This is the complete API surface Scope exposes today: two endpoints.
Everything else the app does (reading/writing jobs, employees, and so
on) goes directly from the browser to Supabase, governed by Row Level
Security, not through a route documented here.

There is no external/partner integration today -- this page exists so
one exists the moment Scope needs it, and so the API's own team has one
place describing exactly what these two routes do. See
`docs/audits/2026-08-17-api-security-and-versioning.md` for the audit
and versioning rationale behind this document.

**Base URL:** `https://scope-intake.vercel.app`

**Versioning:** every route lives under `/api/v1/`. A breaking change
(removed field, changed field meaning, new required input) ships as
`/api/v2/...` alongside `/v1/`, never as a silent change to `/v1/`
itself. See `docs/api/changelog.md`.

---

## `POST /api/v1/review-job`

Produces a short AI-generated job brief from a customer's intake
submission, before the job is saved to the database. Called by the
public intake form (`src/ScopeIntake.jsx`) partway through submission.

**Auth:** none. This is a public, unauthenticated endpoint by design --
it runs before a customer has an account or session of any kind.
Protected instead by per-IP/per-company rate limiting and a global daily
cost cap (see the audit doc above).

**Request body** (JSON):

| field | type | required | notes |
|---|---|---|---|
| `summary` | string | yes | Combined text of the customer's answers. Max 6000 characters. |
| `mediaCount` | integer | no | Number of photos/videos attached. 0-8. |
| `mediaTypes` | string | no | Comma-separated media MIME types. Max 200 characters. |
| `subdomain` | string | no | Which company's intake form this is. Max 100 characters. |

**Success response** -- `200`:

```json
{
  "jobType": "Leaking pipe under sink",
  "urgency": "Medium",
  "likelyMaterials": ["PEX", "compression fitting"],
  "briefSummary": "Customer reports water pooling under the kitchen sink since this morning...",
  "watchOutFor": "Confirm shutoff valve location before starting -- customer didn't mention one."
}
```

**Error responses:**

| status | when |
|---|---|
| `400` | `summary` missing/empty/too long, or `mediaCount`/`mediaTypes`/`subdomain` fail validation |
| `405` | method other than `POST` |
| `429` | rate limit or daily cost cap reached (`code` field: `rate_limited_ip` \| `rate_limited_company` \| `global_cap_reached`) |
| `500` | AI service unavailable, or an internal error -- body is always a safe generic message, never a raw internal error |

## `POST /api/v1/check-missed-leads`

Finds jobs unclaimed for over an hour and emails the company's
owner/dispatcher. Called by a scheduled GitHub Actions workflow
(`.github/workflows/check-missed-leads.yml`) every 10 minutes -- not
meant to be called by anything else.

**Auth:** required. Every request must include a header matching the
server's `CRON_SECRET`:

```
x-cron-secret: <secret>
```

A missing or incorrect secret returns `401` before any database access.

**Request body:** none.

**Success response** -- `200`:

```json
{
  "checked": 3,
  "alerted": 2,
  "failed": 1,
  "failures": [
    { "jobId": "b6e2...", "status": 403 }
  ]
}
```

`failures[].stage` is present and set to `"mark_alerted"` when the alert
email sent but the job couldn't be marked as alerted afterward
(otherwise the failure was the email send itself).

**Error responses:**

| status | when |
|---|---|
| `401` | missing or wrong `x-cron-secret` |
| `405` | method other than `POST`/`GET` |
| `500` | missing server configuration (Supabase or Resend credentials), or an internal error -- body is always a safe generic message |
